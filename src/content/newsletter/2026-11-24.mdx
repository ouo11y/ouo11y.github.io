This issue covers two weeks, 9 to 22 November, because last week's issue did not go out. KubeCon
North America week brought no Collector release, but its maintainers set the dates for retiring the
`batch` processor, which nearly every Collector config uses. If you run .NET 8 or 9, read the .NET
item before you take 1.21.0. Collector v0.166.0 and specification v1.63.0 came out on 23 November,
one day after the window; they are in issue #4.

<Item id="batch-deprecated" title="The Collector batch processor is being deprecated" label="deprecation" date="2026-11-11"
  why="Almost every Collector pipeline lists `batch` under processors. Exporter-level batching sits next to the sending queue, which the processor never could, so the two are now configured and sized together."
  todo="Remove `batch` from your pipelines and turn on batching in each exporter's `sending_queue`, as the post shows. Batching now happens after the queue, so the queue holds small, unbatched requests: raise `queue_size`, or size it in items or bytes, before you switch. If you need batching inside a pipeline, use the `queue_batch` processor."
  sources={[
    { label: 'OTel blog: Deprecating the Collector Batch Processor', href: 'https://opentelemetry.io/blog/2026/collector-batching-migration/' },
    { label: 'core v0.165.0 (queue_batch processor beta)', href: 'https://github.com/open-telemetry/opentelemetry-collector/releases/tag/v0.165.0' },
  ]}
  deeper={[{ label: 'Kubernetes observability without a vendor, part 2: the collectors', href: '/blog/k8s-without-a-vendor-2-collectors/' }]}>

The Collector SIG announced the plan on 11 November. Exporter-level batching becomes the default in
most exporters in v0.171.0, planned for February 2027, and the `batch` processor is to be removed
from core and the distributions in v0.177.0, planned for May 2027. The new default alone is not
enough: a config that still lists `batch` will fail once the processor is gone.

</Item>

Released 11 November. Supported targets are now `net10.0`, `net11.0`, `net462` and
`netstandard2.0`. New: .NET 11 support, including enabling activity sources from configuration;
`OTEL_METRIC_EXPORT_MAX_BATCH_SIZE` to split large metric exports; and samplers that are shut down
with their tracer provider. The environment-variable carrier APIs are stable, following the spec
change reported in issue #2. Self-diagnostics now writes rolling `otel-dotnet-*.log` files. The
auto-instrumentation followed on 20 November with v1.20.0, built on 1.21.0 and adding .NET 11.

</Item>

Merged between 9 and 22 November, all unreleased. The `QUERY` value of `http.request.method` is
stable now that the method has an RFC. The conventions gained opt-in counters for Linux Pressure
Stall Information (time stalled on CPU, memory, IO and IRQ), opt-in `system.memory.linux.free`,
`.buffers` and `.cached` metrics next to the memory states deprecated in v1.45.0, and guidance for
duration histogram buckets: 1, 2.5, 5 steps up to 10 seconds, then minutes and hours up to 7200 s.
`db.client.operation.duration` gains the 2.5-step boundaries to match. Kubernetes `k8s.volume.*`
attributes are renamed `k8s.pod.volume.*`.

</Item>

On 17 November the project said blog posts now need an author who is a member of the OpenTelemetry
organization, and that it will strongly prefer project and organization announcements such as
releases and SIG news. The reason given: readers increasingly reach the project through AI tools
and the docs, so review time is better spent on documentation.
