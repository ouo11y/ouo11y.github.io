## The parts

- **The collector is the edge.** Everything enters through an OpenTelemetry Collector: OTLP on `:4318`, replay chunks on `:4319`, each request with a project credential. The ouo11y distribution adds a replay receiver, a rate limiter and a Sentry SDK bridge. You can build your own with the OpenTelemetry Collector Builder.
- **Storage is the LGTM stack.** Loki holds RUM events and logs, Tempo traces, Mimir metrics, all in open formats.
- **rum-api** folds every signal with the same `session.id` into one session record (status, counts, traces, replay) and stores replay chunks on disk or in S3. It is internal: nothing outside the cluster reaches it.
- **Grafana** with the ouo11y app shows session health, the sessions list and a session's timeline, traces and replay, next to every other dashboard you have.

## What a session looks like

Every signal of the visit carries the same `session.id`, so rum-api can put them on one line. One row per signal.

Its status is the worst thing that happened: a fatal exception makes it **crashed**, a failed request or a handled exception **errored**, nothing at all **healthy**. See [Sessions and health](/docs/concepts/sessions/).
