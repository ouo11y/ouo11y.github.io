Two changes. The API sends traces with the OpenTelemetry Node SDK. The shop loads `@ouo11y/browser`, which records every page change by itself, and calls `rum.addEvent` at three moments. Those page views and events are what a funnel counts.

## The API

Stop the API (Ctrl+C in its terminal). Replace `backend/package.json`: it adds the OpenTelemetry packages, and `start` now loads `instrumentation.js` first.

<QuickstartFile qs="tiny-shop-funnels" path="result/backend/package.json" title="backend/package.json" />

Create `backend/instrumentation.js`. It sends traces to the collector with the project credential, and copies the browser's `baggage` (`session.id`, `user.id`) onto every span, so backend spans can be found from the RUM session.

<QuickstartFile qs="tiny-shop-funnels" path="result/backend/instrumentation.js" title="backend/instrumentation.js" />

Replace `backend/server.js`: the same API, plus a `checkout` span with a `charge card` child that records the declined card as an error.

<QuickstartFile qs="tiny-shop-funnels" path="result/backend/server.js" title="backend/server.js" />

```bash
cd ~/Desktop/tiny-shop-funnels/backend
```

```bash
npm install
```

```bash
npm start
```

**Check:** the first line it prints is `[otel] traces to http://localhost:4318`.

## The shop

Stop Vite (Ctrl+C in its terminal). Replace `frontend/package.json`; it adds `@ouo11y/browser` 0.2.1:

<QuickstartFile qs="tiny-shop-funnels" path="result/frontend/package.json" title="frontend/package.json" />

Create `frontend/src/rum.js`. Two settings matter for funnels:

- `session: { sampleRate: 1 }` keeps every session. A funnel counts sessions, so sampling would scale every step down.
- `replay: { enabled: true, sampleRate: 1, maskAllInputs: true }` records every session with inputs masked, so you can watch the ones that drop. The card number is not in the replay.

<QuickstartFile qs="tiny-shop-funnels" path="result/frontend/src/rum.js" title="frontend/src/rum.js" />

Replace `frontend/src/main.jsx`, so the SDK starts before React renders:

<QuickstartFile qs="tiny-shop-funnels" path="result/frontend/src/main.jsx" title="frontend/src/main.jsx" />

Replace `frontend/src/App.jsx`. Compared with the plain shop:

- **Pages need nothing.** The SDK records every page load and every `pushState` as a `navigation` event with `url.path`. Those are the funnel's page steps.
- **Three custom events:** `rum.addEvent("add_to_cart")`, `rum.addEvent("checkout_submitted")` and `rum.addEvent("order_paid")`. Those are the event steps. Their attributes (`product.id`, `order.total`) are kept on the event and shown on the session timeline; a funnel matches the name only.
- The API URL comes from `rum.js`, and a declined payment is reported with `rum.captureError`.

<QuickstartFile qs="tiny-shop-funnels" path="result/frontend/src/App.jsx" title="frontend/src/App.jsx" open={false} />

```bash
cd ~/Desktop/tiny-shop-funnels/frontend
```

```bash
npm install
```

```bash
npm run dev
```

The funnel you build later uses five of these rows: `navigation /`, `navigation /products/1`, `add_to_cart`, `navigation /checkout`, `order_paid`.

## What you should see

In Grafana (http://localhost:3000) open **More apps → ouo11y RUM → Sessions** and open the newest session, yours. Its activity list has `Navigation` entries for `/`, `/products/1`, `/cart`, `/checkout` and `/orders/...`, with `add_to_cart`, `checkout_submitted` and `order_paid` between them. The replay plays your clicks, with the card field masked.
