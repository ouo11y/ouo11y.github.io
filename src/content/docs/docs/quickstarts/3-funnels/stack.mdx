## The collector

The collector is the only thing your apps talk to. It checks the project credential (`projects.htpasswd`) and routes traces to Tempo, logs (the SDK's page views and custom events) to Loki, and replay chunks to rum-api. It also copies the OTLP event name into the `event.name` attribute, which Loki turns into a label.

## Loki

Loki stores the browser's events: a `navigation` event with `url.path` for every page, and the custom events. These are the funnel steps. `event_name` becomes a label, so rum-api can fetch one kind of step in one query.

## Start it

The collector image on ghcr.io is public, so there is nothing to log in to.

Point the builds at your clone and start everything. The first run builds rum-api and Grafana, two to three minutes:

```bash
export OUO11Y_REPO=~/ouo11y
```

```bash
docker compose up -d --build
```

<Aside>
`OUO11Y_REPO` lives in this terminal only. If you open a new terminal for the stack later, export it again before any `docker compose up`.
</Aside>

## What you should see

rum-api has the funnel endpoint. An empty funnel gets a 400, not a 404:

```bash
docker compose exec grafana curl -s -X POST http://rum-api:8080/v1/funnels/query -H 'Authorization: Bearer rt_dev_0000000000000000' -d '{"steps":[]}'
```

It prints:

```json
{"error":"a funnel has 2 to 10 steps"}
```

Open http://localhost:3000 and sign in as admin / testing567. **More apps → ouo11y RUM** has a **Funnels** page. It is empty for now.

Ports taken by another stack? See [When something does not work](/docs/quickstarts/3-funnels/replay/#when-something-does-not-work).
