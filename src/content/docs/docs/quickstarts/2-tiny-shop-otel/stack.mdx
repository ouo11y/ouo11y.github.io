## 4a. Create the files

Six services, one folder each. Each folder holds that service's compose file and its config, and each file starts with what the service is for, who sends it data and its ports. Open a block, copy all of it, and paste it into the file named in its title. VS Code creates the folders when you save a new file as `stack/10-collector/compose.yaml`.

`compose.yaml` only lists the service folders:

**The collector** is the only thing your apps talk to. It checks the project credential (`projects.htpasswd`) and routes traces, logs, metrics and replay chunks.

Two parts of the collector config matter for a browser you instrument yourself. The `cors` blocks let a page on `localhost` call the collector, and they list the headers your code sends: `traceparent` and `baggage` on OTLP, `X-Ouo-Session-Id` and `X-Ouo-Seq` on replay. And `transform/events` copies the OTLP event name into the `event.name` attribute, which Loki turns into a label.

**The three stores**: Tempo for traces, Loki for logs and browser events, Mimir for metrics. This shop sends no metrics yet; Mimir is there so the collector's `/v1/metrics` has somewhere to go.

<Aside title="Image versions">
The three ouo11y images use the `latest` tag, which follows every release. The compose files say which version this guide was tested with and its digest: pin `ghcr.io/ouo11y/rum-api:0.5.0`, or the `@sha256:...` digest, to keep a stack on one version. The configs in this guide are written for the tested versions; a much newer rum-api may refuse a config key it no longer knows, and the error in `docker compose logs rum-api` names it.
</Aside>

<Aside type="note" title="Development credentials">
The `demo` project token (`pt_dev_demo_0000000000000000`), the Grafana login (`admin` / `testing567`) and the `it_dev_` and `rt_dev_` tokens are public development values. Use them on your own machine only.
</Aside>

## 4b. Pull the images

The ouo11y images on ghcr.io are public, so there is nothing to log in to. Pull them now, about 1.5 GB, so the start is quick. From `tiny-shop-otel/`:

```bash
docker compose -f stack/compose.yaml pull
```

Every image ends as `Pulled`.

## 4c. Check the ports

The stack publishes 3000 (Grafana) and the collector's 4318 (OTLP) and 4319 (replay) to your network, and 3100, 3200, 9009 and 13133 on loopback only. This prints nothing when they are all free:

```bash
lsof -nP -iTCP -sTCP:LISTEN | grep -E ':(3000|3100|3200|4318|4319|9009|13133) '
```

If something is listed, do not stop it: move this stack instead. From `stack/`:

```bash
code .env
```

and set the ports that are taken, for example:

```ini title="stack/.env"
OUO_GRAFANA_PORT=13000
OUO_OTLP_HTTP_PORT=14318
OUO_REPLAY_PORT=14319
```

Compose reads `.env` on its own. The others are `OUO_LOKI_PORT`, `OUO_TEMPO_PORT`, `OUO_MIMIR_PORT` and `OUO_COLLECTOR_HEALTH_PORT` (the `${OUO_..._PORT:-...}` lines in the compose files). Remember the new collector ports: [step 5](/docs/quickstarts/2-tiny-shop-otel/backend/) and [step 6a](/docs/quickstarts/2-tiny-shop-otel/browser-spans/) tell you where they go.

## 4d. Start it

In the third terminal tab, from `tiny-shop-otel/`:

```bash
cd stack
```

```bash
docker compose up -d
```

```bash
docker compose ps
```
