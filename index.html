See every user session, end to end, on infrastructure you own.

ouo11y is OpenTelemetry-native Real User Monitoring. Sessions, errors, crashes, traces and session replay from web and mobile apps, joined to your backend traces and shown in Grafana. No proprietary format, no lock-in.

What you get

Everything a RUM product does, built on the standard.

Every signal is OTLP with OpenTelemetry semantic conventions. It lands in the LGTM stack you may already run, and it stays yours if you ever leave.

Sessions with a lifecycle

Sessions start, rotate and end by a written spec: inactivity, max duration, backgrounding or crash. Each one is classified healthy, errored or crashed.

Session replay

rrweb replay for the web, one replay per session in ordered chunks. Inputs are masked by default, and replay can be paused without stopping telemetry.

One timeline

Session start, navigation, errors, requests, traces and session end on one timeline, with replay that seeks to the moment something broke.

Frontend to backend traces

Fetch and XHR calls carry trace context, so a slow checkout opens straight into the Tempo trace that shows which service was slow.

Health by release

Healthy, errored and crashed percentages per platform and app version, so you can tell a bad release within minutes of shipping it.

Runs next to Sentry

The ouo11y bridge accepts Sentry SDK traffic, forwards it unchanged, and turns it into OTel signals and replay. Adopt ouo11y without ripping anything out.

Answers, not dashboards

The questions ouo11y answers on day one.

  1. What share of sessions were healthy, errored or crashed, per platform and app version, in any time range?
  2. Which sessions in the last hour crashed, which user each belongs to, and which traces each one produced?
  3. When did a session start and end, and why: inactivity, max duration, backgrounding or a crash?
  4. What did the user actually see before the error, with requests and traces on the same timeline?

Platforms

Small SDKs, standard wire format.

Install the SDK, point it at your collector, and sessions start flowing. Any service already instrumented with OpenTelemetry joins the same traces with no extra work.

Web@ouo11y/browser React Native@ouo11y/react-native iOSouo11y-ios Any backendOpenTelemetry Android · Kotlin · Flutterplanned 
import { initRUM } from "@ouo11y/browser";

const rum = initRUM({
  endpoint: "https://otel.example.com",
  projectId: "web-store",
  projectToken: "pt_...",
  service: { name: "web-store", version: "1.4.2" },
  tracing: { propagateTo: [/api\.example\.com/] },
  replay: { enabled: true, maskAllInputs: true },
});

rum.setUser({ id: "user-42" });
// sessions, errors, Web Vitals, fetch traces
// and replay now flow over OTLP.

Open by design

Self-hosted, open licences, your data.
